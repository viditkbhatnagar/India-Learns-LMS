2. Cast of characters — the five roles

India Learns has five distinct roles. Each sees a different dashboard and has different powers.

SUPER ADMIN

Super Admin

System owner. Full read access everywhere — including faculty private notes via oversight. Creates Admin accounts. Configures the whole tenant.

ADMIN

Admin

The operator. Creates courses, batches, programs. Enrols students. Assigns faculty. Resolves tickets. Has rights to undo past 7-day windows.

FINANCE

Finance

Money mover. Records payments, generates receipts, tracks fee installments, triggers suspensions when invoices go unpaid past warnings.

FACULTY

Faculty (Teacher)

Daily teaching. Takes attendance. Runs sessions. Grades assignments. Provides feedback. Cannot create courses, only teach what's assigned.

STUDENT

Student

The learner. Sees published courses on their dashboard. Attends classes (marked by faculty), submits assignments, views grades after publish.

4. Phase 1 — Authoring in the Curriculum Generator

Before a course exists in the LMS, it's built in the Curriculum Generator — an AI-assisted authoring tool that converts a Subject-Matter Expert's outline into a complete 13-step course package.

Who's involved

SME

Subject-Matter Expert

An industry expert. Fills in the Excel template that seeds the workflow.

CURRICULUM LEAD

Curriculum Lead

Reviews AI output between steps. Edits where AI got it wrong. Approves to advance.

AI

OpenAI (via Generator)

Generates content for each step using RAG over an approved knowledge base.

Key tech detail: Steps 10, 11, 12 are queued module-by-module (one Bull queue per step). A 6-module course generates assignment packs for module 1 first, then auto-chains to module 2, etc. This means a course gets ready in waves, not all at once.

Output of Phase 1

A CurriculumWorkflow document in MongoDB with all 13 step outputs. The Generator does NOT push to the LMS automatically — Admin pulls it in (next phase).

What gets created

2
ModulesOne per logical grouping — built from Step 4's MLOs (Module Learning Outcomes).
3

7. Phase 4 — Sandbox → Published

The state flip that turns a course live.

Course state machine
stateDiagram-v2
  [*] --> Sandbox: Admin imports / creates
  Sandbox --> Sandbox: Faculty reviews,
edits order,
fixes typos
  Sandbox --> Published: Admin clicks "Publish"
(confirmation dialog)
  Published --> Published: Live teaching
attendance, grading
  Published --> Archived: Course end-date
auto-archive
  Archived --> [*]

Before publishing, Admin checks

  • Faculty has reviewed all sessions and confirmed the content is correct.
  • Timetable is set — students need to know when class meets.
  • Fee structure is set — students will see their invoice.
  • All enrolled students have set their password (or at least have the invite).
  • The first session's materials (deck, PDF) actually open in the slide viewer.

What happens at the moment of publish

1
Admin clicks PublishConfirmation dialog: "This will make the course visible to all enrolled students. Continue?"
2
State flips in MongoDBcourse.state = "published" + audit log entry.
3
Notifications fireEach enrolled student gets an email + in-app + WhatsApp: "Your course X is now live."
4
Faculty's dashboard updatesCourse badge changes from "Sandbox" to "Published". Attendance + grading now work.
5
Students see the courseNext dashboard load: course appears with module list, first session highlighted.
Reversible? Yes — Admin can flip back to Sandbox, but students lose access until re-published. Not recommended once teaching has started. Use only if a major content issue is found.

10. Phase 7 — Grading workflow (the two-step flow)

India Learns's grading is deliberately two-step: faculty save drafts privately, then publish when ready. Editing a published grade auto-reverts it to draft.

Submission state machine
stateDiagram-v2
  [*] --> NotStarted: Assignment created
  NotStarted --> Submitted: Student submits
  Submitted --> Submitted: Resubmit
(if window open)
  Submitted --> GradedDraft: Faculty saves draft
  GradedDraft --> GradedDraft: Faculty edits
(score / feedback)
  GradedDraft --> Published: Faculty clicks Publish
  Published --> GradedDraft: Faculty edits
(auto-revert)
  Published --> [*]: End of course
  Submitted --> Missing: Past due, no submission
  Missing --> Submitted: Late submission accepted

Grading sequence — one student, one assignment

Grading sequence
sequenceDiagram
  participant Student
  participant LMS
  participant Faculty
  participant N as Notification Service

  Student->>LMS: Submit assignment (text + files)
  LMS->>LMS: state = submitted
  LMS->>N: Notify faculty (in-app)
  Faculty->>LMS: Open grading screen
  Faculty->>LMS: Score: 17 / 20
Feedback: "Solid work…"
  Faculty->>LMS: Click "Save draft"
  LMS->>LMS: state = graded_draft
(invisible to student)
  Faculty->>LMS: Reopen, edit score → 18
  Faculty->>LMS: Click "Publish"
  LMS->>LMS: state = published
  LMS->>N: Notify student (email + WA + in-app)
  Student->>LMS: View grade + feedback
Why two steps? Forces a deliberate "I'm sure" moment before a grade goes visible. Faculty can refine privately as many times as they want. No accidental sends.

Bulk publish

From the gradebook, faculty can select multiple draft rows and bulk-publish in one action. One audit log entry per row. Notifications fire for each student.

The 7 reminder fire points

  1. Day −3 before due — gentle reminder.
  2. Day 0 on due date — "Payment due today".
  3. Day +3 — "Overdue, please pay".
  4. Day +7 — Warning 1: "Account at risk".
  5. Day +14 — Warning 2: "Final warning, suspension imminent".
  6. Day +21 — Auto-suspension triggered. Course access removed.
  7. Day +28 — Escalation to Admin for manual review.

17. Cross-cutting — Audit log & oversight

Every write by a staff role (Admin, Finance, Faculty) is logged. Super Admin can review.

What gets logged

  • admin Course create/edit, batch create, enrolment, faculty assignment.
  • finance Payment recorded, receipt generated, suspension flipped.
  • faculty Attendance saved, session complete, grade saved/published.
  • system Auto-suspensions, certificate issuance, scheduled job results.

Each log entry contains

{ actor, action, target, before, after, at, ip, userAgent }
Super Admin oversight: Can read (not edit) every record in the system, including faculty private notes. Used only for incident review, never routine.

SMESubject-Matter Expert. The industry professional who seeds a course with the Excel template.

PublishedA course state. Live and visible to enrolled students.

SessionA single lesson. Has its own page with materials + attendance.
